# 物品统计 UI 与数据说明

更新：2026-11-03。当前已接入真实库存与本地缓存；不调用 isearch、不操作物品；筛选及栏宽保存于独立settings.json。实现与验证边界见 [真实库存统计](INVENTORY.md) 与 [设置保存](SETTINGS.md)。

## 界面约定

- 主窗口首次默认 1280×780，最小 1000×520，保证三栏与固定五列卡片可读；旧窗口尺寸由卫月保留，首次尺寸不会强制覆盖已有布局。
- 左中右初始按 18:54:28 分配宽度，扩大右栏默认空间；本次调整使用新的布局标识以应用新比例，之后仍可拖动两条竖向分隔线调整栏宽。各栏独立滚动；中间标题、状态图例与右侧统计口径固定在列表上方。
- 左侧默认按物品分类、15 个 4.0 职业全部勾选；按职业分类时切换为主手、70级校服、优雷卡补正、小黑衣 / 小红衣四个勾选框，默认全选。两种模式的筛选互不影响。
- 按物品分类时共享装备只出现一次，任一适用职业被选择即可显示；按职业分类时按装备对应职能重复显示。材料按装备 key 去重，不按展示次数累计。
- 中间每行固定 5 个紧凑矩形卡片，常规字号下宽度上限 110、高度约 82，按字体缩放适配；空间不足时宽度缩小，空间充足时五列网格整体居中、两侧留白。名称保持放大 15%，缩减职业、名称、圆点之间的留白，文字行距收紧 5%。显示最终装备名去除阶段后缀的部分。悬停显示阶段名称与状态。
- 按物品分类时，麒麟大袖与朱红斗篷从普通补正防具中分出，在列表最后以“小红衣 / 小黑衣”单独展示，仍受对应职业筛选影响、照常计入材料。
- 按职业分类时，每个职业分三行：第一行主手与对应麒麟大袖/朱红斗篷，第二行五件校服，第三行五件元素补正防具；不再添加末尾衣服组。被筛选掉的行不显示。衣服由“小黑衣 / 小红衣”独立勾选控制，共享物品跨职业显示时材料照常去重。
- 主手的常风、元素、涌火、最终形态与改装为大圆点，其他中间阶段为小圆点；校服的四个阶段与元素防具的三个阶段均为大圆点，独立兑换的成品只有一个大圆点。
- 亮绿色表示已获取库存中实际持有的阶段，允许多个；前置配方推算已完成的点用浅绿色，后续点为灰色空心。没有任何库存时显示未获取，离线预览仍可使用模拟数据。
- 右栏材料卡片改为紧凑矩形，常规字号下宽度上限 90、高度约 74（随字体比例缩放），收紧名称、数字和底部进度条的留白；仍按四岛及印章/织物分成五行（3/3/2/3/2 件）。每行独立居中，窄栏卡片与文字同步缩小，数字避免在数值中间断行。筛选无需求的材料和空分组略去。

## 预览与来源状态

游戏内默认使用真实库存，不提供示例开关。来源状态为本会话已读取的绿色“已更新”、仅历史记录的灰色“已缓存”、从未获取的灰色“未获取”；悬停可看最后获取时间。

读取范围为背包、穿戴、兵装库、普通/高级陆行鸟背包、幻化柜、收藏柜，以及每个雇员的背包、穿戴和货架。幻化柜套装只计入实际存放的部件；未获取来源不算空，保留上次有效快照。数据按当前角色隔离，无外部 IPC 依赖。

`StatisticsPreview` 内的持有装备、材料数量全部是内存示例，仅供 `tools/UiPreview` 离线绘制；生产窗口的统计来自 `InventoryTracker`。

统计口径（均针对当前筛选的唯一装备集合）：

- 全部所需 T：所选装备从首个制作阶段到最终阶段的固定材料总数。
- 已投入 S：由真实拥有装备的强化前置链推算最低已完成成本，不重复累加旧阶段或共享装备，也不是终身制作流水。
- 目前持有 H：各已获取/已缓存来源中对应材料的堆叠数量合计。
- 按目前进度：`H / (T - S)`，分母不扣除材料库存 H。
- 按总体进度：`(H + S) / T`。进度条限制在 0～100%，数字保留原值。
- 悬浮兑换缺口：`max(0, T - S - H)`，对应兑换需求向上取整。各材料独立估算，不分配兑换资源、不扣除兑换材料库存，不自动执行兑换。
- 乱属性水晶按用户指定的 `1 常风水晶 ≈ 3.5 乱属性水晶` 估算，显示“约”与整数。这个 3.5 是产品假设，不声称是 Wiki 固定兑换率。

## 数据范围

`Data/StatisticsCatalog.cs` 保存 UI 名称与阶段材料事实；真实物品 ID 在 `Inventory/ResolvedCatalog.cs`、`GameCatalogLoader.cs` 通过本机 Lumina 表解析，已校验 665 个相关 ID。字符串 key 仅是界面标识，不作为游戏物品 ID。

- 15 个拥有禁地兵装路线的职业主手。
- 骑士用“安忒亚”卡片代表剑盾整套，包含柏勒洛丰，按剑盾合计材料展示，防止整套强化材料重复统计。后续若拆成单独盾牌卡片，必须核实各阶段剑盾分摊成本。
- 15 职业 × 5 部位 = 75 件常风校服，完成阶段为 `·常风`。
- 7 职能 × 5 部位 = 35 件元素防具，完成阶段为 `+2`。
- 5 件麒麟大袖与 2 件朱红斗篷，合计 7 件独立兑换补正防具，加入优雷卡补正分类。元素武器的改装已在主手路线内，不在补正分类重复建卡。
- 总计 132 张唯一装备卡、13 种固定需求材料。
- 职业限定 4.0 的 15 个职业：骑士、战士、暗黑骑士、白魔法师、学者、占星术士、武僧、武士、龙骑士、忍者、吟游诗人、机工士、黑魔法师、召唤师、赤魔法师。后续和设限职业均不显示；共享补正装备仍保留七种职能的完整物品范围。
- 视觉尖角帽、闪袭指环、凯西耳坠属于恒冰的专用效果装备，本版补正分类按“元素加持”解释，未混入仅加速的装备。
- 爆炎乱属性水晶用于随机属性调整，每次 2 个，次数不确定，右栏用说明展示，不编造完成总数。
- 旧化的 290 品原型装备是前置条件；这里的固定材料统计不将其与消耗材料混计。常风校服与元素防具是独立路线。

用户指定的六个页面均已通过浏览器读取正文；普通网页抓取返回 403，搜索索引仅作辅助。物品名称来自禁地兵装的武器、防具总览，材料由四岛强化表交叉核对。这里只整理游戏数据事实，不复制攻略正文。

## 验证与预览

`tools/UiPreview` 使用本机卫月自带的 ImGui 程序集与 cimgui，直接调用同一份页面代码，在独立进程内离线绘制，不加载或操作游戏。中文字体使用 Windows 微软雅黑；皮肤与字体可能和游戏内不同。

```powershell
dotnet run --project tools/UiPreview -- statistics.png
dotnet run --project tools/UiPreview -- small.png --small
dotnet run --project tools/UiPreview -- by-job.png --job --overall
dotnet run --project tools/UiPreview -- unknown.png --unknown --one-job
dotnet run --project tools/UiPreview -- empty.png --empty
```

生成的 PNG 在 `artifacts/ui/`。预览工具校验 132 个唯一装备 key、职业映射、示例阶段边界与总材料；验证重复传入共享装备不会重复计材。另以 ImGui 输入事件验证单选与职业勾选，并生成阶段/兑换悬浮预览。

已目视检查：1000×520、1280×780、1600×1000，物品分类、职业分类、总体口径、单职业且未获取、全部取消、悬浮提示。游戏内实际字体、热重载、输入及滚动仍需独立验证。
# 最新显示调整（2026-11-03）

常风/恒冰/涌火/丰水/改造分别使用黄绿/蓝/红/蓝绿/棕色；装备实际持有用亮色，推算前置用浅色，未拥有保留空心灰色。每个阶段按其配方材料所属阶段配色，水晶、低保与兑换材料的数字/进度条和兑换提示同色。校服属常风，元素防具三阶段属涌火/丰水/改造，印章与织物用棕色。恒冰材料行改为恒冰水晶、结冰乱属性水晶、娄希的冰片，不改变成本计算。默认/最小窗口离线检查通过。
