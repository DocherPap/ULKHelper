# 优雷卡助手：开发 context

更新日期：2026-11-03。

## 用户目标与当前范围

新项目“优雷卡助手”，基于 FF14 卫月（Dalamud）：

1. 优雷卡相关装备及对应材料速览。
2. 一部分刷怪、刷材料及其他功能自动化。

初始化后，用户明确要求先建立简单 UI：窗口可调整大小，所有组件适应窗口大小；上方分页选择，下方页面主要内容，先提供“自动化”和“物品统计”两页。装备与材料范围已经核实；已授权先实现独立玩家列表、车头消息监听和目的地导航 helper，最后再整合。后续接入天气预报；最新任务新增四岛地图、FATE 点位和类似 ACT 的计时，现为四个等宽页签。

物品统计 UI 为四类装备（主手、70级校服、优雷卡补正、小黑衣 / 小红衣），左侧分类与职业筛选/来源状态，中间固定每行五个装备卡片与阶段圆点，右侧两种口径的材料卡片与兑换提示。用户已授权真实库存统计与交互时更新。最新要求：卡片紧凑矩形、收紧行距，只保留 4.0 的 15 个职业，衣服作为独立筛选分类。完整库存机制见 `docs/INVENTORY.md`；新实现的自动化 helper 见 `docs/AUTOMATION_HELPERS.md`。

## 当前实现

- `ULKHelper.csproj`：沿用 MakoMaster 的 Microsoft.NET.Sdk + 本机程序集引用，暂不引入 NuGet 包或打包 SDK；引用程序集不复制到输出。
- `ULKHelper.json`：API 15、版本 `0.0.1.0`（发布标签 v0.0.1）；作者 DocherPap，目标仓库 DocherPap/ULKHelper。
- `Plugin.cs`：服务构造注入、注册 `/ulk`、创建真实 `InventoryTracker` 并注入窗口，卸载时完整反注册并保存缓存。
- `Windows/MainWindow.cs`：可调整大小的 WindowSystem 主窗口，首次默认 1280×780，最小 1000×520；顶部依次为等宽的“物品统计”“天气预报”“地图 / FATE”“自动化”页签。
- 页面使用每帧填满剩余空间的 child 区域，内容溢出时在页面内部滚动，页签保留在顶部；文字按可用宽度换行。后续输入组件按可用宽度布局，多列内容在窄窗口下重排，禁止固定坐标布局。
- 四个顶部选项卡均分可用宽度：每帧扣除页签间距后各取四分之一，随窗口缩放更新。
- `Data/StatisticsCatalog.cs`：Wiki 核实的 15 条主手路线、75 件常风校服、35 件元素防具与 7 件独立兑换补正装备；13 种固定材料及兑换关系。`Inventory/GameCatalogLoader.cs` 和 `ResolvedCatalog.cs` 通过本机 Lumina 表解析真实逐阶段物品 ID 与配方，已核实 665 个相关 ID、652 个装备阶段输出。
- `Windows/ItemStatisticsPage.cs`：三栏响应布局，初始 18:54:28（本次更新新布局标识以扩大默认右栏），两条分隔线支持拖动调整栏宽；两种分组/筛选、来源状态预览、装备阶段、材料卡片、悬浮兑换提示。
- 装备卡片为宽度上限 110、高约 82 的紧凑矩形（随字体缩放），五列网格居中；名称保持放大 15%，行距收紧 5%。按物品分类时，麒麟大袖/朱红斗篷属于第四类“小黑衣 / 小红衣”，在列表末尾显示。
- 按职业分类时仅显示 4.0 的 15 个职业；每个职业第一行主手和对应衣服，第二行校服，第三行元素补正装备。衣服由第四个勾选框独立控制，空行省略，材料去重规则不变。
- 右侧材料卡片宽度上限 90、高约 74，按常风、恒冰、涌火、丰水、印章与织物分成五行（3/3/2/3/2），每行独立居中。窄栏卡片和文字同步缩小，无需求的材料/空分组不显示。
- `Inventory/InventoryTracker.cs`：框架线程读取背包、穿戴、兵装库、普通/高级鸟包、收藏柜、幻化柜（含已存套装部件）、逐雇员背包/穿戴/货架；监听库存变动和窗口开关，平时 750ms 节流、事件后约 250ms 检查。无主动服务器请求/游戏操作。
- `Inventory/OwnershipLedger.cs`：每角色、每雇员、每来源独立数量快照，区分未获取、缓存、本会话已更新；原子保存，坏缓存保留，登出/切角色清空当前统计。
- 更新状态 UI 中每个雇员只显示一条“雇员 名称”，不展开背包/穿戴/货架；任一部分本会话读过即显示已更新，只有历史记录显示已缓存，均未读取则未获取。仅合并展示，底层快照与库存统计范围不变。
- `Inventory/IStatisticsProvider.cs`：真实库存投影、前置配方推算、共享装备/剑盾配方去重；数量与已投入分开统计。
- `Windows/StatisticsPreview.cs`：示例数据仅用于独立开发预览；生产窗口必须注入真实提供者，不显示示例开关。
- `tools/UiPreview`：使用本机 ImGui 依赖离线绘制同一页面的开发工具，不进入插件编译或分发输出；验证截图在忽略的 `artifacts/ui/`。
- 没有 isearch 依赖；库存仍无原生hook。全岛玩家名单新增ContentMember.EndRequest完成通知hook，卸载释放；已新增本地发布脚本及库链配置。真实库存保存在插件配置目录下 `inventory/<角色ID>.json`，筛选不持久化。新增导航使用可选 vnavmesh IPC，其余功能不依赖它。
- `Automation/PlayerListHelper.cs`：每秒读取当前已加载玩家的托管快照，客户端对象表无法覆盖整张地图远端玩家。
- `Automation/LeaderListenerHelper.cs`：名字＋原始服务器选定车头；监听 Say/Yell/Shout，保留 50 条原始消息，优先识别 MapLinkPayload，回退 `(x, y)`；当前地图坐标距玩家 ≤25m 跳过，其余地图标记。默认关闭，切区/实例/角色清空，不保存车头。
- `Automation/DestinationNavigationHelper.cs`：独立 Start/Tick/Stop，附近 50m 查进行中的优雷卡 NM（本地 Fate.EurekaFate=1/Rule=1，排除幸福兔），初始 25m 站位；无 NM 等 2 秒；接近终点 50m 时改 30m 站位，仅一次。手动开始、可停止、5 分钟时限，状态异常/切区/死亡/战斗等停止。
- `Automation/VnavmeshAdapter.cs`：本机 vnavmesh 1.2.3.14，使用可取消路径计算、地面查询、路线读写 IPC。只取消自身 token、匹配自身路线后停止，不用全局 CancelAll；晚到结果不会自动移动。依赖缺失只影响导航。
- `Windows/AutomationPage.cs`：可拖动两栏、玩家搜索/选择、开始/停止监听、地图目的地、消息记录；最新已增加已拥有坐骑下拉和开始/停止跟随伐木，将导航/同步/循环/BossMod整合为显式启用的流程。见docs/FELLING_FOLLOW.md。
- 最新天气接入：参照用户提供的 `https://ulk.tunnel.tidebyte.com:8129/weather`，核实其为前端本地计算，不使用在线预报接口。新增 `Weather/WeatherForecastHelper.cs` 纯计算、`WeatherCatalogLoader.cs` 读取四岛 WeatherRate；无新增网络/插件依赖。
- 天气页显示四岛当前及后续共 6/12/24 段、下一段倒计时、本地或 UTC 时间、日期与 ET，按窗口宽度及字体换行，上下滚动。
- 天气数据核实：TerritoryType 732/763/795/827 对应 WeatherRate 91/94/96/100；概率与参考网站一致，生产读取本地表。每段 1400 秒，uint32 哈希计算；详情和来源见 `docs/WEATHER.md`。仅展示，尚未用于自动化触发。
- `Fates/FateSeeds.cs` / `FateCatalogLoader.cs`：cactbot 版本 `8d12b650896aed42e56bcfe07c8580426ab2b9f8` 提取的四岛72点位（67 NM+5幸福兔），本机 Fate 表解析全名/等级并全量校验；GameMap 414/467/484/515，读取本机纹理，不分发地图图片。丰水 Map 515 OffsetY=475，必须正确处理偏移。
- `Fates/FateMapTracker.cs` / `FateLedger.cs` / `FateTiming.cs`：框架线程0.5秒读取实际FATE起点/剩余/进度/状态；单次入场托管记录，未知历史不猜。预计冷却从出现时间计算（常规120分钟，特殊例外见数据）；天气/ET夜间条件窗口复用天气helper。表中暂时消失只标过期，不伪造击杀。切区域/地图/实例/角色清空，无跨房间缓存。
- `Windows/FateMapPage.cs` / `GameMapTextures.cs`：四岛切换/跟随当前岛、缩放平移、简称/幸福兔开关、玩家位置、可拖动两栏、点位搜索选择和游戏地图标记；当前岛可手动补记0–240分钟前出现。计时是“预计 / 待触发”，不代表必定刷新。未联网史书或接入自动移动。
- 点位数据的 Apache-2.0 许可证与出处在 `ThirdPartyNotices/`，构建时复制；后续发布须保留。完整设计和测试见 `docs/FATE_MAP.md`。
- 最新授权接入 `https://ce-crowdsource.atmoomen.top/`，用户随后明确“只在进岛的时候读取一次”。`Crowdsource/CrowdsourceClient.cs` 使用官方公开 `POST /v1/subscriptions` + 返回的官方快照GET；每次入场一次，无轮询/续期/失败重试/心跳/上传/WebSocket。网站官方接口已实测200订阅+200 JSON快照（样例区域空tracks），并非依赖其他插件私有桥接API。
- `ZoneServerIdReader` 从Zone Init记录读取真实房间ID（Server ushort高16位+Instance ushort低16位），只读动态签名；当前游戏磁盘文件唯一匹配manager和offset签名，偏移0x5D0，执行仍动态解析。框架线程不跨帧保留指针，只保存RVA/偏移。未取得稳定房间号时不查询。大区取当前世界DataCenter，ContentId仅用于本地会话隔离，不上传。
- 入场等待2秒并确认房间号稳定1秒再查询。按DC/房间/岛屿校验响应，最新track单独导入；null/未来/过期/非FATE不填入。当前本地活动或更近记录优先；众包记录标来源，不当作活动实时状态。离岛取消旧任务，重新入场才允许再查，不能把未完成请求写入下一房间。见 `docs/CROWDSOURCE.md`。
- `FateTriggers.cs` 已按网站官方目录版本c2bf132ca39c1467c60bb87b97c3281160ae3c80整理72条触发说明（小怪等级/名称、天气夜间、UFO/塔内及幸福兔特殊情况），附MIT许可证。右侧列表、选中详情和地图悬浮均显示。
- 地图点位直接显示“刷新剩余 / 天气等待 / 天气剩余”，包括当前活动的下一次预计冷却；右侧仍显示活动进度/本次剩余。即使无历史也可展示天气窗口，连续同名天气段合并；没有记录且没有时段条件的仍显示未记录。标签按字体计算并尝试避让。

## 装备材料当前边界

- 装备、阶段和材料已整理在目录与 `docs/ITEM_STATISTICS.md`；四岛为常风、恒冰、涌火、丰水。本机 `2026.10.06.0000.0000` 数据解析已验证全部 Item RowId 与路线总成本；实际游戏交互仍待验证，TerritoryType ID 尚未使用。
- 装备名称、图标、职业、物品基础属性优先读取 `IDataManager` / Lumina 本地表，避免把中文名称当主键。
- 装备强化链、兑换成本、获取来源独立建模。基础物品表不等于完整获取关系；配方与掉落需另外核实并记录来源。
- 建议模型包含物品 RowId、阶段、前置装备、材料与数量、区域、来源说明、已核实版本。不要先编造 ID 或材料数量。
- UI 可按职业、装备类别、阶段和区域筛选，展示单阶段需求与到目标阶段的累计需求。
- 持有量、材料缺口、前置阶段推算已接入真实快照；柜子和雇员须实际打开获取，未加载时不能凭空刷新。已有缓存按上次获取结果计入并明确标注，出售中物品可能在两次访问之间售出。
- 数据目录、业务服务和 UI 按实际功能新增，首版不要求外部联网服务。

## 自动化后续方向

- 用户已明确授权并完成跟随伐木整合：默认不启用，选择坐骑/车头后显式开始，战斗中不切换目的地，结束关闭控制并上坐骑。游戏内验证待进行；不自行扩展到其他刷怪任务。
- 其他刷怪/材料流程待明确：目标怪物/材料、数量、路线、是否涉及技能执行、目标选择、拾取或兑换，以及期望的停止/恢复条件。
- 预计拆分观察游戏状态、任务状态机、动作适配和可选 IPC；先确定一个可验证的小流程。
- 设计候选状态：Idle / Running / Paused / Completed / Failed；只在框架线程执行游戏操作，各步骤有超时与结果确认，不在 UI Draw 中执行动作。
- 手动停止、离开目标区域、登出、死亡、切区或依赖失效时如何处理，应在实现具体动作时定义；登录或重载后默认不自动恢复任务。
- 导航已接入可选 vnavmesh 并核对本机接口，实际优雷卡网格和移动仍需游戏内验证。尚未接入 Lifestream 或跨区域移动。
- 停止只撤销本插件拥有的操作，处理寻路异步返回造成的“停止后又开始移动”等竞态。
- 官方仓库对战斗干预和自动化有限制，不能预设本项目可提交官方仓库。当前仅本地开发，未来分发方式待定。见 [Plugin Restrictions](https://dalamud.dev/plugin-publishing/restrictions/)。
